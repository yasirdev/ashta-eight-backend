# Ashta Eight — Backend

R1 REST API: Node/Express + TypeScript + Prisma over PostgreSQL (Row-Level Security).

**Status:** Architect stage only — data model + RLS. Business logic/routes are built
by Agent 1 (Backend) against the FROZEN `/contracts/contracts.md`.

## What's here now
- `prisma/schema.prisma` — the R1 data model (all tables).
- `prisma/migrations/` — the generated DDL migration (extensions, enums, tables, indexes).
- `prisma/rls/000_roles.sql` — the two DB roles (`ashta_app`, `ashta_service`).
- `prisma/rls/policies.sql` — RLS policies (deny-by-default, ownership/tier/role).
- `prisma/rls/verify.sql` — RLS assertion test (ownership/tier/auth-secret isolation).
- `prisma/seed.sql` — the 4 programmes + a dev administrator.

## Bring the schema up (local dev)
```bash
cp .env.example .env          # set real DATABASE_URL / role passwords
npm install
createdb ashta_eight          # or CREATE DATABASE ... owned by the migration user
npm run db:setup              # migrate → roles → RLS → seed → verify (one command)
```
`db:setup` runs on a **fresh** database. It applies migrations, creates the two roles,
applies RLS policies, seeds, then runs `db:verify` (fails loudly if RLS isn't enforced).
Individual steps: `db:roles`, `db:rls`, `db:seed`, `db:verify`.

**Re-running:** `policies.sql` uses `CREATE POLICY` (not idempotent), so to rebuild from
scratch run `npx prisma migrate reset` first, then `npm run db:setup`.

**Note (raw-SQL writers):** PK `id` defaults are generated by Prisma Client, not the DB —
any raw-SQL insert (seed / service-role SQL) must supply `id` (`gen_random_uuid()`) and
`updated_at` (`@updatedAt` columns have no DB default). Writes via Prisma Client handle
both automatically.

RLS is not managed by Prisma; `policies.sql` must be re-applied after any migration that
adds/renames a table. Folding it into the migration history (so `migrate deploy` alone
secures the DB in CI) is recommended before production — flagged for human hardening.

## RLS model (read before building endpoints)
- Runtime request handlers connect as **`ashta_app`** and set, per request:
  `SET LOCAL app.user_id = '<uuid>'; SET LOCAL app.user_role = '<role>';`
- System/cross-owner flows (register, login, tokens, Stripe webhook, FCM logging,
  anonymous questionnaire, cron reminders) connect as **`ashta_service`** (BYPASSRLS).
- Everything else is denied by default. See `policies.sql` header for the full model.
